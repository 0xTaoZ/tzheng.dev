## Keeping the homepage and cases in sync

The homepage previously held separate copies of project summaries and article text. Updating a detail page could leave the card describing an earlier version.

The homepage now uses native Astro components. Typed Markdown records supply the cards, indexes and detail pages; a dated contribution snapshot supplies upstream links and derives its totals from the records. The original dark presentation, Earth background, terminal and animations are retained.

## Frontend structure

Page sections are separate components. Styles and interaction code are served as local assets, including the utility styles previously generated by a third-party script in the browser. Article cards link to full routes, so the unused modal reader and its duplicate article bodies have been removed.

## Delivery and limits

Astro builds a static artifact for GitHub Pages. Visitors can read the content without fetching it through a client API. Accounts, sessions and a database would add no useful capability to the current site.

Content and types are checked before building; the generated pages are checked for broken internal links. Presentation work also requires desktop and mobile browser review.

[System Design](/system/) is the current technical reference for the schema, build and delivery path. This case describes the maintenance problem and resulting behavior.
