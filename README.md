# tzheng.dev

[Haitao Zheng’s portfolio](https://tzheng.dev): security tooling, cloud
infrastructure, project case studies and technical writing.

## Development

Use Node.js 24 and npm. Run `npm ci`, then `npm run dev`.
Verify with `npm run check`, `npm run build` and `npm test`.

## Content and presentation

The homepage is composed from `src/components/home/` by
`src/pages/index.astro`. Its original presentation is retained in local CSS and
interaction assets; no browser-time CSS compiler is required.
Shared design tokens (colours, type, spacing) live in `src/styles/tokens.css`;
`home.css` styles the homepage and `global.css` the content pages. Erode (Fontshare) and
JetBrains Mono (Fontsource) are self-hosted. Articles and project case studies use typed Markdown collections;
existing detail URLs are preserved. A single sitemap integration generates
the index, with last-modified dates from frontmatter and the contribution
snapshot; the postbuild step preserves `/sitemap.xml` as an alias.

The contribution snapshot lives in `src/data/contributions.json`. Run
`npm run contributions` (requires an authenticated `gh`) to refresh merged
PRs, merge dates, repository stars and the open-PR count together with the
verification date, then review the diff. Homepage totals, the monthly chart
and the contribution ledger are derived from that file.

## Motion

Homepage motion lives in `src/motion/`. `core.ts` runs Lenis smooth
scrolling from the GSAP ticker and keeps ScrollTrigger in sync; each effect
registers as a scene (`scenes.ts`, `hero-gl.ts`, `skyline.ts`) and a failing
scene never breaks the page. The hero backdrop is a raw WebGL fragment
shader; the contribution skyline loads Three.js only when it nears the
viewport. Content pages load `smooth.ts` (Lenis only). Reduced motion, data
saver and very small devices get the static page; without scripts, CSS
scroll-driven animations handle reveals. Animate only `transform` and
`opacity`, and check new effects for layout shift and long tasks.

## Images and share cards

Optimized portrait, logo and education images live in `public/img/` and are
generated from the originals in `public/` by `npm run images`. Share cards
(1200x630) live in `public/og/` and are generated by `npm run og` from the
content collections; run it after adding or renaming an article or project.
Both outputs are committed, so the Pages build does no image processing.

The résumé at `/resume/` is generated from the same records. After changing
it, run `npm run build && npm run resume:pdf && npm run build` to refresh
`public/haitao-zheng-resume.pdf`; the script fails if it no longer fits on one
A4 page.
`npm test` fails when a page points at a missing share card.

## Publishing

A push to `main` uses `.github/workflows/deploy.yml` to check, build and deploy
the static artifact to GitHub Pages. Keep this single deployment path.

## Article publishing

Add Markdown to `src/content/articles/`. The collection validates titles, slugs,
publication dates, categories, tags and status. `draft` and `archived` entries
are excluded from routes, the archive, homepage and RSS. The monthly archive
supports local full-text search and category filtering without a service.
All articles remain available when JavaScript is disabled.

`date` is the actual publication date. Optional `seriesMonth` (YYYY-MM) groups
an article into a monthly reading series about a topic or period of work; it
never overrides the publication date in the article, feed or structured data.
New companion guides explicitly describe when they were written. Preserve
original publication dates when updating older notes, and set `updated`.
`readingTime` is optional; without it the page estimates it from the body.
Optional `homepageOrder` selects the three homepage reading recommendations.
Set `project` to a case-study slug when a note explains that project. The build
rejects unknown project references. Related notes are ranked by the same
project, then shared tags, then category. The archive search ranks matches
by title, tags, excerpt and body, and keeps `?q=` and `?category=` in the URL.

`/search.json` is generated at build time from pages, project cases and
articles. The site-wide command palette (⌘K, Ctrl+K or `/`) fetches it on
first use and ranks matches by title, tags, metadata and body.

No database or authentication service is needed for this editorial workflow.
Revisit that choice if a browser-based multi-author editor, reader accounts or
comments become requirements. Content changes use the same checked Pages build.
